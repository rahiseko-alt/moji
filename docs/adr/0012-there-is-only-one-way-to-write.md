# 書き方は1つだけにする（テストを封印する）

練習とテストの2つを作ったが、両者の棲み分けが決まらなかった。点線とお手本を
出すか出さないか、答え合わせをその場でするか最後にまとめるか、という違いは
付けたものの、「学生がどちらをいつ使うのか」に答えが無いまま画面だけが2通りに
分かれていた。決まっていない区別を残したまま作り続けると、判定や画面を触る
たびに「テストのときはどうなる」を考え続けることになる。

そこでテストを画面からもコードからも外し、書き方を1つにした。表紙から選び欄が
消え、点線・お手本・先回りのナビは常に出る。用語からも「練習」「テスト」を
消した。選べないものに名前を残すと、次に作るときその名前に引きずられるため。

## Consequences

テストにしかなかった動きは失われる。点線もお手本も出さないこと、選んだお題を
全部書き終えるまで結果を出さないこと、の2つである。合わせて30行ほどで、
作り直すときは、そのとき決めた棲み分けに合わせて書き直す方が速い。

テストを作り直すなら、先に答えるべきはこれである。「テストは何を試すのか」。
形と筆順を手で書けるかを試すなら、書く字は見せてよい（見せないと何を書くか
わからない）。字を思い出せるかを試すなら、読みや意味から書かせることになり、
それは単語データ（#9）が入ってから初めて作れる。
